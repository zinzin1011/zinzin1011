# 회의 종료 → 노션 반영

Claude API 를 쓰지 않는다. 분석은 지금 이 대화에서 직접 하고, 노션 기록만 스크립트로 한다.

## 1. 녹음 종료
```bash
./mb record stop
```
출력의 파일 경로를 `AUDIO` 로 기억한다. 파일은 RECORD_DIR(구글 드라이브 동기화 폴더)에 있어 자동 업로드된다.
(사용자가 기존 녹음 파일 경로를 줬다면 1단계를 건너뛰고 그 파일을 `AUDIO` 로 쓴다.)

## 2. 받아쓰기 + 화자 구분 (내 Mac 에서, 수 분 걸림)
```bash
./mb transcribe "$AUDIO"
```
- 오래 걸리니 타임아웃을 넉넉히(최대치) 잡는다. 사용자에게 "받아쓰는 중(1시간 회의 기준 몇 분)"이라고 한 줄 알린다.
- 결과는 `AUDIO` 와 같은 이름의 `.txt`. 각 줄은 `[시:분:초] [화자N] 말`.

## 3. 분석 규칙 가져오기
```bash
./mb schema
```
`rules` 와 `schema` 를 따른다. 사람 이름·유형·분야는 schema 의 enum 값만 쓸 수 있다.

## 4. 화자 이름 매칭
- 녹취를 읽고 화자N 을 팀원 이름(schema 의 참석자 enum)과 짝짓는다.
  근거: 자기소개, 서로 부르는 이름, 역할 언급(PM·데이터·백엔드·프론트·인프라 등).
- 확실하지 않은 화자가 있으면 그 화자의 대표 발언 2줄을 보여 주고 사용자에게 누군지 묻는다. 추측으로 채우지 않는다.

## 5. 분석 JSON 작성
- 녹취 전체를 읽고 schema 에 정확히 맞는 JSON 을 `AUDIO` 와 같은 이름의 `.analysis.json` 으로 저장한다.
- 회의 날짜·시각은 파일명 `YYMMDD_HHMM_...` 에서 얻는다. 상대 날짜("다음 주 수요일")는 회의 날짜 기준으로 계산.
- 화자 구분 결과 덕분에 "제가 할게요" 같은 발언의 담당자를 말한 사람으로 정할 수 있다.

## 6. 미리보기 후 노션 반영
사용자에게 짧게 보여 준다: 회의명, 핵심 결정, Action Items(담당/기한), 추가될 일정.
사용자가 확인하면(또는 처음부터 "바로 올려"라고 했으면) 실행:
```bash
./mb project --transcript "<녹취.txt>" --analysis "<.analysis.json>" --date YYYY-MM-DD --time HH:MM
```
`--author` 는 `.env` 의 `MEETING_AUTHOR` 가 기본값이다.

## 7. 마무리
출력된 노션 회의록 링크와 "의사결정 N건 · 일정 N건 추가"를 한두 줄로 알린다.
